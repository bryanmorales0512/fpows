Project Overview
1 / 4
FPOWS is a custom-built automation platform that sits on top of REDMEN's live simPRO instance (redmen.simprosuite.com). It eliminates manual job lookups, automates call sheet emails, writes asset service dates back to simPRO, and delivers daily and bi-weekly management reports — all without any manual data entry.

Roadmap — Upcoming Work
3 / 4
Priority Feature Description & Business Value Status
Short Term Persistent Email History Email history currently resets when Cloud Run container restarts. Move to a persistent store (Cloud Storage or Firestore) so no history is ever lost between deployments. NEXT
Medium Term GoFormz Integration Auto-fill GoFormz inspection forms using simPRO job data — client name, site address, asset types, service dates. Eliminates double data entry for field technicians. PLANNED
Medium Term Mobile-Friendly UI Responsive redesign so technicians can use FPOWS on phones and tablets in the field — view jobs, send call sheets, and update asset dates on site. PLANNED
Medium Term Individual User Logins Replace the single shared admin key with per-user authentication (Google OAuth or similar). Enables audit trails, permission levels, and personalised dashboards. PLANNED
Long Term Analytics Dashboard Visual charts showing call sheet volume over time, overdue site trends, service date compliance rates, and which customers are contacted most frequently. PLANNED
Long Term FRED Enhancements Expand FRED's capabilities — natural language queries ("show me all overdue Major clients"), proactive alerts, and integration with the daily report for voice-style summaries. PLANNED
KNOWN ISSUES (as of May 2026)
  • Email history resets on container restart (Cloud Run ephemeral filesystem)
  • node-cron re-registers on every cold start — Cloud Scheduler is the reliable fallback
  • No per-user login — single admin key shared across team
  • Customer search cache is in-memory — resets on restart

  • req.body undefined crash on /api/presence/leave → fixed with || {} guard
  • Rate limit values in docs were incorrect → corrected to match code
  • FPOWS Assistant renamed to FRED across all UI and emails

  • Service due dates with no asset record → shows "—" instead of inferred job date
DEPLOYMENT PROCESS
  • Test locally: yarn dev → verify at localhost:3000
  • Deploy to production: .\deploy.ps1
  • Script reads .env, injects all env vars into Cloud Run
  • gcloud builds Docker image from source (--omit=dev)
  • Cloud Scheduler job recreated at 6am Asia/Manila
  • Total deploy time: ~2–3 minutes
